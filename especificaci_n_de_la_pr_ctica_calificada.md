# PRÁCTICA CALIFICADA 1
## Desarrollo de una Aplicación Web: Gestión de Liga de Básquetbol

---

> **Modalidad:** Individual  
> **Plataforma de Control:** Repositorio en GitHub  
> **Duración total:** 4 semanas  

---

### 1. Objetivo

Desarrollar una aplicación web que permita gestionar la información de una liga de básquetbol, integrando funcionalidades de autenticación, gestión de equipos, jugadores y partidos, aplicando buenas prácticas de desarrollo de software y control de versiones.

---

### 2. Descripción de la Aplicación

La aplicación deberá permitir la gestión integral de una liga de básquetbol mediante los siguientes módulos funcionales:

* **Autenticación:** Registro e inicio de sesión de usuarios.
* **Equipos:** Gestión completa (crear, editar, listar y eliminar).
* **Jugadores:** Gestión y asignación de jugadores por equipo.
* **Partidos:** Registro y control de encuentros deportivos.
* **Estadísticas:** Visualización de resultados y métricas básicas de la liga.

---

### 3. Requerimientos Técnicos

| Componente | Especificación |
| :--- | :--- |
| **Lenguaje principal** | PHP |
| **Base de Datos** | MySQL o MariaDB |
| **Control de versiones** | Git |
| **Repositorio remoto** | GitHub |

---

### 4. Metodología de Desarrollo

El desarrollo del proyecto deberá realizarse utilizando control de versiones con Git, aplicando buenas prácticas de la industria:

* **Estrategia de ramas:** Uso de ramas por funcionalidad (*feature branches*).
* **Historial de cambios:** *Commits* frecuentes, atómicos y con mensajes descriptivos.
* **Integración:** Uso de *pull requests* para fusionar cambios.
* **Trabajo progresivo:** El avance debe evidenciar actividad continua a lo largo del periodo asignado.

---

### 5. Documentación Técnica (OBLIGATORIA)

El estudiante deberá elaborar un documento técnico que describa el desarrollo del sistema, redactado formalmente como si estuviera dirigido a un equipo de desarrolladores.

#### Características del Documento:
* **Extensión:** Entre 500 y 800 palabras.
* **Ubicación obligatoria:** `/doc/practica_liga.md` dentro de la raíz del proyecto.

#### Contenido Mínimo Requerido:
1. **Arquitectura:** Descripción general de la arquitectura del sistema.
2. **Componentes clave:** Listado detallado de clases, controladores y modelos implementados.
3. **Funcionalidades:** Descripción técnica de las principales funcionalidades desarrolladas.
4. **Código fuente:** Explicación y desglose de fragmentos relevantes de código.
5. **Resolución de problemas:** Dificultades encontradas durante el desarrollo y soluciones aplicadas.
6. **Decisiones de diseño:** Decisiones técnicas tomadas y su respectiva justificación.

---

### 6. Entrega del Proyecto

La entrega se realizará a través de la plataforma **Classroom**, cumpliendo estrictamente con los siguientes entregables:

* **Archivo comprimido (`.zip`):** Conteniendo la totalidad del proyecto.
* **Historial Git intacto:** El archivo `.zip` debe incluir obligatoriamente el directorio oculto `.git`.
* **Enlace web:** URL directa al repositorio público o accesible de GitHub.
* **Documento técnico:** Archivo `/doc/practica_liga.md` incluido en el proyecto.

> ⚠️ **IMPORTANTE:**  
> No se aceptarán trabajos que no evidencien el uso regular de control de versiones o que hayan sido desarrollados de manera no progresiva (por ejemplo, proyectos con todos los *commits* concentrados en una sola fecha o subidos en un único bloque).
